### Q1 の答え — 3 層は「載る」が、**層ごとに欠け方が違う**

| 層            | shadcn + Tailwind                                            | 判定                                                                                    |
| ------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| **primitive** | Tailwind が **419 件**すべて供給                             | 🟦 **過剰なほど有る**。ただし「参照専用で直接は使わない」規律は**誰も強制していない**      |
| **semantic**  | **色は 18 件有る。spacing と typography は 0 件**            | 🟥 **半分欠けている** → DR-0019 で自前定義すると決定                                       |
| **component** | 🟨 **有る**。`--sidebar-*` 8 ＋ `--card-spacing` ＋ 幅 2 の計 11 | 🟨 **DR-0012 の「component token 無し」は不正確だった**（下記）                            |

> ⚠ **DR-0012 の理解を 1 つ訂正する。**手1 では「shadcn は実質 semantic 1 層で component token 無し」と読んでいたが、
> 実測すると **component token は存在する**——`--sidebar-*`（8・`globals.css`）と `--card-spacing`（`card.tsx` の任意プロパティ）。
> **思想の 3 層は 3 層とも shadcn 側に実在する。**欠けているのは層ではなく、**semantic 層のうち spacing / typography** だけ。
> → 手順書 §5 H2-02 の「判断」欄が予告していた分岐に該当。§2 へは追記せず、**発見として実行記録と DR に落とす**。

### Q4 の答え — Tailwind の `--spacing` / `--text-*` は **primitive**

- `--spacing` は **0.25rem という値が 1 個あるだけ**で、段の名前すら存在しない（`p-4` は `calc(0.25rem * 4)` の糖衣）。
- `--text-xs..9xl` は**サイズ名**。用途は一切言っていない。
- 対して tmp-admin は `--text-body` / `subhead` / `footnote` を持ち、4.3 で「**本文 body、テーブル本文 subhead、th/補助 footnote**」と
  **用途で使い分けを規定している**。つまり写す先が Tailwind 側に無い。
- → **semantic 層を自前で足す**（[DR-0019](DR/DR-0019-semantic-spacing-typography-vocabulary.md)）。

### Q3 の答え

**「accent 衝突」は、当初 DR-0005 が想定したより浅い。**
`preset=nova` の `--primary` は **ブランド色ではなく無彩色（ほぼ黒）**なので、そこに tmp-admin の accent を入れないという**写し方の選択だけで V2 の色の側は守れる**。
残るのは「塗り CTA という**形**」であり、これは色ではなく `button.tsx` の variant 定義の問題＝**部品を触らないと消えない**。

🟥 **より重い衝突は #7（タッチターゲット 44px）だった。**apple 系が「不可侵の下限」とした値を、shadcn nova は既定で割っている。
これはトークンでは解けず、**思想（値の出所）とプリセット（部品の形）の設計思想が正面からぶつかる唯一の点**。→ 手3 の判断へ送る。
