# DR-0010: shadcn 自身が任意値を発明している — 手5 の判定は二値にできない

## 背景

[共通コンポーネント思想](../共通コンポーネント思想.md) ① Tokens 層の目的は「**AI が margin/padding を毎回発明する**」を止めること。手1 で shadcn の素のコードに任意値禁止 lint を当てた。

## 発見

**shadcn の素のコードは任意値を 24 件含む。しかも思想が止めようとしたのと同じ「値の発明」を、shadcn 自身がやっている。**

24 件を「**トークンを差し替えたら追従するか**」で分けると 4 種類に割れた。

| 分類 | 件数 | 例 | 手5 への影響 |
|---|---|---|---|
| (A) トークンのみで構成 | 4 | `bg-[color-mix(in oklch,var(--secondary),var(--foreground) 5%)]` | 🟦 追従する |
| (B) トークン + 生値の混合 | 6 | `rounded-[min(var(--radius-md),10px)]` | 🟨 生値部分は固定 |
| **(C) 純粋な生値** | **8** | `text-[0.8rem]` `rounded-[4px]` `min-w-[96px]` `ring-[3px]` | 🟥 **追従しない** |
| (D) 値ではない | 6 | `transition-[width]` `grid-cols-[1fr_auto]` | 🟦 影響なし（→ DR-0011） |

## 根拠（実測）

`pnpm lint` の JSON 出力を集計（手1・部品 18 件）。全 24 件の内訳は [部品カタログ 表5](../部品カタログ.md#表5-任意値の分類q2-の答え--手5-の判定に直結) に列挙。

**(C) 8 件の所在**: `badge.tsx` `ring-[3px]` / `button.tsx` `text-[0.8rem]` / `checkbox.tsx` `rounded-[4px]` / `dialog.tsx` `max-w-[calc(100%-2rem)]` / `dropdown-menu.tsx` `min-w-[96px]` / `sidebar.tsx` `after:w-[2px]` / `tooltip.tsx` `translate-y-[calc(-50% - 2px)]`・`rounded-[2px]`

## 影響

🟥 **「箱を触らずテーマだけ変える」（PoC の OBS-0003）は、shadcn をそのまま使う限り最初から部分的にしか成立しない。**

したがって **手5 の判定方法を変える必要がある**:

- ❌ 変わったか / 変わらなかったか の二値
- ✅ **「どこが変わらなかったか」を列挙する**形。(C) の 8 件と (B) の生値部分が変わらない箇所として先に分かっているので、**それ以外に変わらない箇所が出るか**が実際の観測点になる

対処の選択肢（手3 で決める）:
1. (C) を含む部品だけラップして生値をトークンへ置換する（＝部品を触る）
2. 生値を許容し、「テーマ差し替えで変わらない部分」として明示的に受け入れる
3. トークン側に該当する semantic token を足し、部品を書き換える
