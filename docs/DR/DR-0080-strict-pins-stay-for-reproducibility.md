# DR-0080: 依存の厳密ピンは残す — 理由を「工場の再現性」へ書き換える

## 背景

[DR-0003](DR-0003-foundation-mirrors-poc.md) は土台を「PoC と同一版・同一 lint の単体 Next.js アプリ」と定め、
厳密ピンの理由を「移送できたかの判定を信用させるため」に置いていた。
PoC への移送が消えた（[DR-0078](DR-0078-repo-becomes-a-ui-factory-for-a-core-design-system.md)）ので、この理由は成立しない。
**やっていること（ピン）は正しいまま、理由だけが失効した**形。

## 決定

1. **厳密ピン（`^` なし）は続ける。**理由は「PoC と同一版だから」ではなく——
   - **再現性**: 工場の出荷物は「この版の組で動く」ことまで含めて資産。lock と catalog の二重管理も版の暗黙更新も避ける。
   - **観測の 1 変数化**: 本 repo の方法論は毎回 1 変数だけ動かして測ること。依存の自動更新は無断で変数を増やす。
2. **lint 構成（`no-arbitrary-value` ほか）も維持する。**出どころは PoC だが、**工場自身の規約として引き取る**。
   「本 repo で緑でも PoC で緑とは限らない」という DR-0003 の帰結は消滅。
3. **「単体 Next.js アプリ」の部分は工程1 で Vite ライブラリに置き換わる**（[工場の段取り.md](../工場の段取り.md) 工程1）。
   `src/` と PoC の 1:1 対応・`paths` 差分の管理は不要になる。
4. **[DR-0003](DR-0003-foundation-mirrors-poc.md) は superseded**（本書が置き換える）。

## 根拠（実測）

- ピンの実務効果は本 repo 自身が実測している——依存を固定していたから、7 周・6 本のゲートの差分を
  常に「自分が動かした 1 変数」に帰属できた（実行記録の全周）。
- 版の暗黙更新が観測を壊す実例は shadcn の `^` レンジ 7 件で既に把握している（[DR-0016](DR-0016-shadcn-deps-are-caret-ranges.md)）。

## 影響

**観測から直接言えること**

1. 工程1 で依存が入れ替わるとき（`next` 削除・`vite` 系追加）も、新しい版は厳密ピンで入れる。
2. `exactOptionalPropertyTypes: false` の「借金」（DR-0014）は「移送時に赤が復活する」という返済期限を失った。
   ただし**借金自体は残る**——返すかどうかは工程1 の tsconfig を決めるときに判断する。

**🟥 推論（未検証）**

- git 依存で使い回す先が現れたとき、厳密ピンが**消費側の依存解決と衝突する**可能性がある（peerDependencies の切り方は未設計）。
  最初の使い回し先で実測する。
