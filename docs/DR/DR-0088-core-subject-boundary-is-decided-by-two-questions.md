# DR-0088: コア / 題材の判定は 2 問で行う

## 背景

工程2 がコア / 題材の線を**暫定的にディレクトリで**引き（[DR-0087](DR-0087-fetching-belongs-to-the-subject-layer.md)）、
規則の起草を工程3 に残した（段取り 未決 #6）。候補は「**コアは語彙（有限集合）、題材は対応表**」。
工程3 で固有物（Redmine 固有の知識）が画面・フィルタ・期間の 3 系統でまとめて現れたので、
**追加・変更した全ファイルから固有物を拾い、候補規則を全件に当てた**（手順書 P3-08）。

## 決定

**判定は次の 2 問を順に問う。**

1. **その知識は、Redmine を知らない repo でも意味が通るか。**
   通らないなら**題材**（`src/redmine/**` / `src/mocks/**`。出荷しない）。通るならコア候補。
2. **（コア候補について）見た目・振る舞いの選択を有限の語で言えるか。**
   言えるなら**語彙**（union / props）としてコアが持つ。言えない（無限・自由文・合成）なら
   コアは**器**（children / slot / 引数の口）だけを持ち、中身は使う側に返す。

付則:

- **語彙の値 ↔ 実物の対応（表）は常に題材へ**（`status.id → tone`・プリセット → 日付範囲・`><` 記法）。
- **語彙は固定ではない。**題材が需要を運んだとき **1 語ずつコアへ昇格**させる（下記 `all` の実例）。
- 問 1 で題材に倒れたもののうち**対応表ですらないもの**（画面の合成・選択肢・既定値・文言）は
  **題材の本文**と呼ぶ——器の中身としてだけコアを通過する。

## 根拠（実測）

工程3 の追加・変更ファイルを 1 本ずつ見て固有物を拾い、候補規則「コアは語彙、題材は対応表」を当てた。

| # | 固有物 | 場所 | 候補規則で説明できたか |
| --- | --- | --- | --- |
| 1 | ステータス選択肢（未完了=open / 完了=closed / すべて=\*） | `IssueList.tsx` `STATUS_OPTIONS` | 🟦 **当たる**（コアの Select は語を知らない・対応表は画面） |
| 2 | 期間プリセットの実体（週の起点・四半期の定義） | `period.ts` `resolvePeriod` | 🟦 **当たる**（コアは 5 語の union だけ） |
| 3 | `updated_on` のフィールド名と `><a\|b` 演算子記法 | `client.ts` / `period.ts` | 🟦 **当たる**（記法は対応表側） |
| 4 | camelCase → snake_case の翻訳 | `useIssues.ts` | 🟦 **当たる**（対応表） |
| 5a | 列の書式（numeric / emphasis） | `IssueList.tsx` `COLUMNS` | 🟦 **当たる**（コアの語彙 `kind` / `emphasis` で宣言） |
| 5b | **どの列を出すか** | 同上 | 🟥 **当たらない**（語彙でも対応表でもない） |
| 6 | 画面の合成（AppShell > PageHeader > FilterBar > DataGrid > Pagination の並び） | `IssueList.tsx` | 🟥 **当たらない** |
| 7 | ナビの構造（チケット / ガント / EVM / 稼働表） | `IssueList.tsx` `NAV` | 🟥 **当たらない**（表と強弁できるが、実際の判定は「出荷しない」が決めた） |
| 8 | 既定値（`PAGE_SIZE=10`・`sort=updated_on:desc`・既定 open / all） | `IssueList.tsx` | 🟥 **当たらない**（方針・既定値） |
| 9 | 文言（ブランド名・パンくず・「期間（更新日）」） | `IssueList.tsx` | 🟥 **当たらない**（本文） |
| 10 | モックの挙動（status_id 既定 open・limit 100・記法の解釈） | `handlers.ts` | 🟥 **当たらない**（対応表ではなく実 API の模倣） |
| 11 | コア側 story に居る題材の語（例示の選択肢・4 ビュー名） | `FilterBar.stories.tsx` ほか | 🟥 **当たらない**（既に「story は題材を見てよい」の機械化例外で処理済み） |

- **当たった 5 件は全部「語彙 ↔ 対応表」の対に割れた**——候補規則はこの範囲では 5/5。
- 🟥 **当たらなかった 6 件は「対応表」ですらない**（本文）。これらを裁いたのは
  「**出荷して他所で意味が通るか**」（問 1）で、実務では D1（画面は `src/redmine/screens/`）の
  ディレクトリ判断として現れていた。
- **語彙が動いた実例**: 一覧（最初の利用者）の既定は「期間で絞らない」なのに union に無かった →
  **`all` を 1 語昇格**（`PeriodSelect`）。「語彙は固定ではない」の根拠。

## 影響

**観測から直接言えること**

- 候補「コアは語彙、題材は対応表」は**前半しか裁けない**。固有物 11 件中、対応表の形をしていたのは 5 件。
- ディレクトリ境界（DR-0087）と 2 問は両立する——問 1 の答えがそのまま置き場（ディレクトリ）になる。
- 判定規則は**素材層 / 製品層の判定（DR-0070・見た目の管轄権）とは別の軸**で、衝突しなかった
  （工程3 で両方を同時に使った: FilterBar の見た目は DR-0070、選択肢の置き場は本 DR）。

**🟥 推論（未検証）**

- 問 1 の「他所で意味が通るか」は**使い回し先が 1 つも無い現在は思考実験**でしか検算できない。
  2 つ目の使い回し先（DR-0078 の狙い）が出たときに、この問いの判定が実測に変わる。
- 工程4（編集）で「編集の状態管理」という新種の固有物が来る。2 問で裁けるかが次の検算。
