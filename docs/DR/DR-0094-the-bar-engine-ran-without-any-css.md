# DR-0094: 完成バーの実行エンジンは CSS を 1 行も当てずに走っていた

## 背景

[部品1](../手順/部品1_完成バーを機械で閉じる.md) B1-02 で `@storybook/addon-vitest` を入れ、
`vitest.config.ts` を書いた。そのファイルの冒頭コメントは、**実ブラウザを選んだ理由**をこう書いている:

> 🟨 **jsdom ではなく実ブラウザ**にするのは、この repo が測りたいものが **実効スタイル**
> （DR-0090 語彙クラスが tailwind-merge に落とされる／`getComputedStyle` で初めて分かる）と
> **a11y のコントラスト**だから。jsdom は CSS を計算しないので、どちらも測れない
> ＝「対象 0 件で緑」になる。

[部品2](../手順/部品2_9カテゴリの充足.md) C2-05 で、バーの**面④（語彙 prop の効果）**を
`play` 関数で測ろうとしたところ、新部品 3 件が同時に落ちた。

## 発見

- **落ちていたのは部品ではなく測定器。**同じ 3 つを実ブラウザ（`storybook-static` ＋ Playwright）で
  測ると全部正しい値が出る。
- 原因は 1 つ: **`vitest.config.ts` は `vite.config.ts` から `resolve.alias` だけを引いており、
  `@tailwindcss/vite` プラグインを引いていなかった。**
  `.storybook/preview.tsx` は `globals.css` を import しているが、その中身は
  `@import 'tailwindcss'` で、**それを展開するのがそのプラグイン**。
  → **runner は素の CSS しか見ていなかった＝ utility クラスが 1 つも生成されていない。**
- ★★ **実ブラウザを選んだ理由に挙げた当のもの（実効スタイルと a11y コントラスト）が、
  実ブラウザの中で動いていなかった。**jsdom を避けた先で、jsdom と同じ状態になっていた。

## 根拠（実測）

同じ 3 つの値を、2 つの経路で測った（2026-08-09）。

| 測るもの | `vitest`（バーのエンジン） | `storybook-static` ＋ Playwright | 正 |
| --- | --- | --- | --- |
| `Switch size="sm"` の幅 | 🟥 **0** | 🟦 **24px** | 24px |
| `Avatar size="sm"` の幅 | 🟥 **16px** | 🟦 **24px** | 24px |
| `Slider` thumb の背景色 | 🟥 **`rgba(0, 0, 0, 0)`** | 🟦 **`rgb(255, 255, 255)`** | 白 |

🟨 **0 / 16px / 透明はいずれも「素の HTML の値」**——中身の無い `<button>` は幅 0、
`<span>小</span>` は文字 1 つぶんの 16px、背景の指定が無ければ透明。**CSS が無い状態と完全に一致する。**

🟥 **`waitFor` では直らなかった**（1 秒ポーリングしても同じ値）＝ **描画待ちの競合ではない。**

`vitest.config.ts` の `plugins` に `tailwindcss()` を 1 行足すと **95 テスト全部が緑**になった。

## 影響

**観測から直接言えること**

- **部品1 が出した「critical 0」は無効にならない。**落とした 11 件はすべて
  `button-name` / `label` / `aria-input-field-name` 系＝ **名前の有無しか見ず、CSS に依存しない。**
- **CSS に依存する面は、この期間まったく測れていなかった**——具体的には
  ① axe の `color-contrast`（🟨 ただし rule 単位で無効化してあったので、そもそも走っていない）
  ② バー面④「語彙の効果」（🟥 **本回が最初の実装で、最初の実行で発覚した**）。
- **「本体から引くから写しを作らない」は、引く項目を選んだ時点で写しになる。**
  `resolve.alias` は引いたが `plugins` は引かなかった。**引かなかったことはどこにも記録されない。**

**🟥 推論（未検証）**

- 面①「描画された」（`document` に 0 でない大きさの要素があること）を機械化していたら、
  **CSS 無しの状態では大量に落ちていた可能性がある**——面① はまだ実装していないので確かめていない。
- 他にも `vite.config.ts` にあって `vitest.config.ts` に無い設定が効いている可能性がある
  （`react()` は `storybookTest` が持つと推測しているが、**測っていない**）。
