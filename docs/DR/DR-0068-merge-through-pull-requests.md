# DR-0068: 手の完了は GitHub の PR でマージする

## 背景

手5・手6 は**ローカルで `git merge --no-ff`**、手7 は **GitHub の PR #1** でマージされていた。
[CLAUDE.md](../../CLAUDE.md) §git は `--no-ff` マージしか書いておらず、**PR は書かれていない。**
打ち方が 2 通りになったので、手8 の着手前に未決 #26 として立てた。

## 決定

🟦 **PR に揃える**（ユーザー判断 2026-08-02）。

- 手ごとに `step/h<N>-<slug>` を切るのは**変えない**
- 完了したら **`gh pr create --base main`** で PR を出す。**マージは人が実行する**
- ローカルの `git merge --no-ff` は**使わない**
- コミット規約（`<type>(H<N>): 日本語要約 [手N]`）も**変えない**

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **A** | ローカル `--no-ff` に揃える | 🟨 速い。🟥 **`main` を別 worktree（`~/conductor/repos/design`）が持っている**ので `-C` の形が必須で、打ち間違えやすい |
| **B** ✅ | **PR に揃える** | 🟦 **差分が GitHub に残る。**手ごとの成果が「何を変えたか」の形で外から読める。🟦 Conductor の worktree 構成と相性がよい（ブランチを切り替えずに出せる） |
| **C** | 両方を認めて CLAUDE.md に併記 | 🟥 **選べる状態は選ばれない。**打ち方が揃わないのが今回の問題そのもの |

## 根拠

- 🟦 **本 repo の成果物は「決定 + 移送可能なコード」**（[DR-0001](DR-0001-repo-role-and-deliverable.md)）。
  **手ごとの差分が外から読める形で残る**ことは、成果物の性質に合っている
- 🟨 **`--no-ff` の利点（マージコミットで手の境界が残る）は PR でも失われない**——
  PR のマージコミットが同じ役割を果たす
- 🟥 **A の運用リスクが実際に効いている**——`main` は別 worktree が持っているので
  作業側から `git switch main` が落ちる。`-C` を毎回書く運用は**手7 の時点で自然に PR へ流れていた**

## 結果

- [CLAUDE.md](../../CLAUDE.md) §git の該当行を書き換えた
- [handoff.md](../handoff.md) の未決 #26 を閉じた
- 🟨 **手5・手6 の `--no-ff` マージコミットはそのまま残す**（履歴は書き換えない）
