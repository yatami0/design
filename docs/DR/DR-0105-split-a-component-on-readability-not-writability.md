# DR-0105: 部品を分ける基準は「既存 API で書けるか」ではなく「書けたものが読めるか」

## 背景

工程5 の本題は「`DataGrid` を拡張するかピボット部品を新設するか」だった。
[DR-0077](DR-0077-abolish-the-two-occurrence-rule.md) で「回数（何回目か）は理由にならない」と決めているので、
**新設するなら回数以外の理由が要る。**

## 決定

- **新設の可否は、まず既存部品で組んでみて、その結果を見てから決める**（工程5 D1=B）。
  🟥 **「書けない」を先に断定しない。**
- **判断基準は「書けたか」ではなく「書けたものが読めるか」。**
  組めてしまうことは、既存部品で足りることを意味しない。
- **新設する場合、理由は「破れた項目の一覧」の形で残す。**列挙されたものが新設の理由の全量。
- 🟥 **既存部品の契約を動かして通す道（`accessor` の引数を増やす等）は選ばない**——
  **その部品を既に使っている画面が本番で動いている。**

## 根拠（実測）

**`DataGrid` の既存 API だけで 92 列のピボットを組んだ**（`src/redmine/screens/Workload.tsx` の初版）。

- **組めた。**`columns` はただの配列なので、日付をクロージャで閉じ込めれば列は動的に生える。
  `th` **94 本**が描かれ、合計は API の総和と一致した（`tools/pivot-probe.mjs` K1-b・K6-b: 306.25 h）。
- **そのうえで 4 点破れた:**

| # | 破れた項目 | 実測 |
| --- | --- | --- |
| ① | **セル単位の符号化ができない** | `kind` / `emphasis` は**列単位**で、`accessor` が返せるのは**セルの中身**だけ。`<td>` の面には手が届かない |
| ② | **行ヘッダを固定できない** | 🟥 `tools/pivot-probe.mjs` K6-f: 右端までスクロールすると 1 列目（`佐藤 花子`）が**器の外**。素材層 `table` は `overflow-x-auto` のみ |
| ③ | **合計行を出せない** | `DataGrid` に footer の概念が無く、`data` に混ぜると `WorkloadRow.user` に実在しない人を入れることになる |
| ④ | 🆕 **列見出しの強弱を出せない** | `<th>` の書式は部品が固定しており、`DataGridColumn` に列見出しの語彙が 1 つも無い（**着手前の予測に無かった 4 点目**） |

- **新設後の実測**: 同じ probe が **13/13 PASS**（K6-f が FAIL → PASS に反転）。
- **①〜④ のどれも「型が通らない」形では現れない。**tsc も lint も、破れた版で緑だった。

## 影響

**観測から直接言えること**

- **予測は 3 点で、実際は 4 点だった。**着手前に列挙した破れ（①②③）に、
  **組んでみて初めて出た ④ が加わった**——**先に断定していたら ④ は出ていない。**
- **①〜④ は「実行して見る」以外の方法では出ない種類の破れ**である。
  型検査・lint・build のいずれも、破れた版を最後まで緑で通した。
- 新設した `PivotTable` は **[DR-0092](DR-0092-the-core-holds-the-vessel-not-the-state.md) の 2 度目の適用**でもある——
  **畳み込みは持たず、畳んだ結果だけを受け取る**（`TimeEntry` も「稼働」も知らない）。

**🟥 推論（未検証）**

- 🟥 **この基準は「読めるか」を人が判定する余地を残している。**②（行ヘッダの固定）は機械で測れたが、
  ①③④ は**「表せない」を実装者が宣言している**形で、機械の裏付けが無い。
  **機械化できるかは分かっていない。**
- 🟥 **「まず既存部品で組む」のコストが割に合わない場面があるはず**だが、
  **その線をどこに引くかは決めていない**（本工程は 1 画面ぶんで済んだ）。
