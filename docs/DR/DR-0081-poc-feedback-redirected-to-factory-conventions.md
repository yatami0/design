# DR-0081: `poc_feedback` は「工場の規約へ戻す候補」に読み替える

## 背景

DR の frontmatter には `poc_feedback`（PoC へ戻す候補の行き先）がある。
PoC への移送が消えた（[DR-0078](DR-0078-repo-becomes-a-ui-factory-for-a-core-design-system.md)）ため、
**77 件全部の出口が宙に浮いた**（[工場の段取り.md](../工場の段取り.md) 工程0 Q2・D3）。

## 決定

1. **フィールド名は変えない。**77 件の一括書き換えは、履歴を汚す割に情報が増えない。
2. **意味を読み替える**——「PoC の規約（ui.md / architecture.md / ADR）へ戻す候補」→
   **「工場の規約へ戻す候補」**。工場の規約とは、本 repo 自身が持つことになる
   ui.md / architecture.md 相当の文書（**まだ存在しない**）。語彙の正本 `.claude/trace.config.mjs` のコメントは更新済み。
3. **既存の値は書き換えず、規約起草時の材料リストとして読む。**
   「ui.md の材料」「architecture.md の材料」という既存の行き先表記は、宛先を PoC から工場へ替えてそのまま通用する。
4. **工場の規約文書の起草はまだしない。**旧・手9 は「移送の直前に規約へ戻す」設計だったが、宛先が自分になったので締切が消えた。
   起草の時機は**使い回し先が 1 つ出たとき、または工程が進んで DR の参照に不便が出たとき**（🟥 回数・件数は理由にしない——[DR-0077](DR-0077-abolish-the-two-occurrence-rule.md)）。

## 根拠（実測）

- **工程0 Q2 の集計**（2026-08-07・全 77 ファイル grep）: `poc_feedback` を持つ DR は **77 件**、
  値が非 null は **64 件**、null は 13 件。
- 非 null 64 件の中身は「ui.md / architecture.md / ADR-0019 / OBS 候補」への行き先が大半で、
  **PoC 固有なのは宛先だけ・内容は工場でも成立する**ことを代表例 3 件（DR-0019・DR-0025・DR-0065）の全文で確認した
  （[実行記録 §工程0](../実行記録.md)）。

## 影響

**観測から直接言えること**

1. 新しい DR も `poc_feedback` を同じフィールド名で書き続ける（意味は工場の規約へ）。
2. [DR/index.md](index.md) 末尾の「poc_feedback 一覧」表は、そのまま**工場の規約の材料リスト**になる。

**🟥 推論（未検証）**

- 「締切が消えた」ことで、規約起草が**永遠に先送りされる**危険がある。64 件の材料は index の表で見えるので、
  工程3〜4（部品が増える工程）の締めで「規約に昇格させるものはあるか」を 1 度ずつ問う。
