# DR-0021: Tailwind v4 は `docs/**.md` まで走査し、文章中のクラス名を本番 CSS に生成する

## 背景

手2 H2-04 で、自前の semantic トークンが本当にユーティリティを生成するかを**赤テスト**で確かめていた
（「定義した名前は効く／定義していない名前は効かない」の両方を見る）。
その最中に、**ページで一度も使っていない `.p-inset-md` / `.gap-inset-md` が生成 CSS に現れた。**

## 発見

**Tailwind v4 の自動コンテンツ検出は `docs/**/*.md` を走査対象に含む。**
ドキュメントの文章やコードブロックに書いたクラス名が、**そのまま本番 CSS のルールとして生成される。**

出所は**手順書 `docs/手順/手2_トークン層マッピング.md` §5 H2-04 のコード例のコメント**（`/* → p-inset-md / gap-inset-md */`）だった。
つまり「手順書に例として書いた文字列」が、アプリの CSS に混入していた。

## 根拠（実測）

2026-07-26。`next build` の出力 CSS を直接検査。

```bash
# 追試: docs に無関係なクラス名を書いてビルドする
echo 'probe: text-fuchsia-700 mt-13' > docs/_probe.md
pnpm build
grep -c 'text-fuchsia-700' .next/static/chunks/*.css   # → 1（生成された）
```

| 対象                             | `@source not` 前 | `@source not` 後 |
| -------------------------------- | ---------------- | ---------------- |
| `text-fuchsia-700`（docs 由来）  | **1**            | **0**            |
| `p-inset-md`（手順書のコメント由来） | **1**            | **0**            |
| `bg-primary`（`src/` 由来）      | 1                | **1**（維持）    |

対処として `src/app/globals.css` に 1 行入れた（手順書 §2 **D9**）。

```css
@source not '../../docs';
```

## 影響

- 🟥 **手5 の判定装置が汚染される。**手5 は「**どこが変わらなかったか**」を列挙する手（[DR-0010](DR-0010-shadcn-invents-values.md)）で、
  生成 CSS を差分で読むことになる。docs に書いた例示クラスが混ざると、**差分がドキュメントの編集で動く**——
  コードを 1 行も触っていないのに CSS が変わる状態になり、観測が成立しない。
- 🟥 **PoC でも同じことが起きる。**PoC は Tailwind v4 かつ `docs/` が巨大（ADR / OBS / framework テンプレート）で、
  **UI 規約や ADR の中に書かれたクラス名がすべて本番 CSS に入る**。バンドルサイズにも効く。→ OBS 候補として手9 で起票する。
- 🟨 逆手に取る使い道もある: **未使用の semantic 語彙は CSS に出ない**（Tailwind が未使用の `@theme` 変数を落とす）。
  これは「定義したのに誰も使っていない語彙」を機械的に検出する手段になる（手3〜手4 で使える）。
- 🟦 `@source not` を入れたのは**仕組みの追加ではなく観測装置の較正**。2 回ルールの対象にしない。
