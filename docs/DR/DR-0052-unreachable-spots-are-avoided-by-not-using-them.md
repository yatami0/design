# DR-0052: 届かない箇所は「使わない」で回避する（目視レビューの結論）

## 背景

手5 の 2 周目で、**レイヤ外上書きは兄弟クラスに届かない**ことが分かった（[DR-0047](DR-0047-cost-of-forcing-the-swap-through.md)）。
`.rounded-lg` を外から潰しても `in-data-[slot=button-group]:rounded-lg` は別のクラスなので当たらず、
variant 側は比率派生のまま取り残される（**7 箇所・うち実測でずれたのは 2**）。

H5-07 の目視レビューで、ユーザーがこの取り残しを見た結論（2026-07-27）:

> 7.2px と 8px はあまり目視では分からないが、**16.8px と 18px は少し違う気がする**。
> でも**そもそも届かないものは使わないでいい気がする**。
> 一旦届かなかった、それはなぜか、ここをドキュメントとして残しておけば OK。

## 決定

**🟦 差し替えが届かない箇所は、上書きを重ねて追いかけるのではなく「使わない」ことで回避する。**

| 手口 | 採否 |
| --- | --- |
| 🟥 variant ごとにレイヤ外上書きを書き足して全部追いかける | **採らない** |
| 🟦 **届かない variant / 部品を「使わない」ものとして扱う** | **採る** |
| 🟨 素材層を書き換えて生値をトークンへ置き換える | 採らない（手5 の前提「素材層を 1 行も触らない」を壊す） |

### 根拠

1. **上書きを重ねる代償が大きい。**[DR-0047](DR-0047-cost-of-forcing-the-swap-through.md) の実測で、
   追従 +29 箇所と引き換えに **shadcn 内部への依存が +9**（`data-slot` 名 2 ＋ ユーティリティクラス名 7）。
   variant まで追いかければこれがさらに増える。
   🟥 **依存は「shadcn を更新できない」という形で返ってくる。**
2. **差が目で分からない。**7.2px と 8px は**目視で判別できなかった**（H5-07）。
   🟨 16.8px と 18px は「少し違う気がする」程度。
   **見えない差のために内部依存を増やすのは割に合わない。**
3. **「使わない」は既に本 repo の作法。**tmp-admin 自身が
   「largetitle〜title2 を使わない」「blur を使わない」という形で**不使用を哲学の一部**にしている
   （トークンマッピング 表4）。**同じ形で扱える。**

### 適用範囲（現時点で「使わない」に該当するもの）

| # | 対象 | なぜ届かないか |
| --- | --- | --- |
| 1 | Sidebar の `variant="inset"` / `variant="floating"` | `md:peer-data-[variant=inset]:rounded-xl` が比率派生のまま（実効 16.8px） |
| 2 | Tooltip の `kbd` スロット | `**:data-[slot=kbd]:rounded-sm` が比率派生のまま（実効 7.2px） |
| 3 | ButtonGroup（`in-data-[slot=button-group]`） | 今は偶然一致しているが、**基数を変えるとずれる** |

🟨 **1〜3 はいずれも本検証（チケット一覧 1 画面）で使っていない。**
「使わない」と決めても**現時点で失うものは無い**。

## 影響

- 🟦 **手5 の Q2 に決着がついた。**「変異を潰さずに済むか」への答えは
  **「潰さずに済む範囲までしかやらない」**。
- 🔺 **ADR 昇格候補。**「どの variant を使わないか」は**外から見える規約**で、
  一度決めると部品の使い方に恒久的に効く。
  🟥 **起案はまだしない**（[DR-0004](DR-0004-document-system-and-git.md) の「判定と起案を分ける」規律。未決 #20）。
  **これで候補は 4 件目**（DR-0032 / DR-0033 / DR-0034 / 本 DR）。
  🟨 **4 件溜まったので、そろそろ起案の時機かもしれない。**
- 🟥 **機械では守れない。**「この variant を使わない」は lint も型も見ない。
  [DR-0032](DR-0032-layout-primitives-take-props-not-classname.md) が「枠は props で閉じる」としたのに対し、
  **本件は props でも閉じない**（素材層の variant なので）。
  → 🟨 **守る手段は 2 つ**（どちらも未決）:
  - **A** 製品層のラッパーで該当 variant の型を落とす（`Omit<Props, 'variant'>` など）
  - **B** 規約として文書に書くだけ
- 🟨 **同じ形が観点 A（不透明度 60 箇所）にも当てはまるか**は**まだ決めない**。
  そちらは[OBS-0009](../OBS/OBS-0009_不透明度と状態面の概念を理解する.md) で概念を理解してから判断する。
