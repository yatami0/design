# DR-0019: semantic な spacing / typography は用途名で自前定義する

## 背景

[共通コンポーネント思想](../共通コンポーネント思想.md) ① Tokens 層は 3 層（primitive / semantic / component）を前提に、
「**Layout / Overlay テンプレが取れる `gap` / `padding` を semantic token に限定する**」と決めている。

しかし [DR-0012](DR-0012-shadcn-supplies-no-layout-no-spacing.md) で **shadcn は spacing / typography のトークンを 1 つも供給しない**ことが判明した。
一方 Tailwind v4 には `--spacing`（1 変数基準）と `--text-xs..9xl`（階調）が既定で存在する。
**この Tailwind 既定を「semantic」とみなせば自前定義は不要**になる。みなすかどうかが手2 の判断ポイント（D2 / D3）だった。

## 決定

**用途名の semantic 層を自前で定義する**（選択肢 B）。ユーザー決定 2026-07-26。

### 比較した 3 案

| 案                                                                | 内容                                                                                | 採否            |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- | --------------- |
| **A** Tailwind 既定を semantic とみなす                           | `--spacing` / `--text-*` をそのまま使い、語彙を増やさない                             | ❌              |
| **B** 用途名の semantic 層を足す                                  | `--spacing-<用途>` / `--text-<用途>` を自前定義。値は既定への参照で書く（手5 まで値は決めない） | ✅ **採用**     |
| **C** B + lint を「用途名以外の spacing / text ユーティリティ禁止」に強化 | 思想が最も強く効く。shadcn 部品も semantic 層に強制的に載る                            | ❌ **今はやらない** |

### A を採らなかった理由

思想の定義（primitive =「生値。参照専用で**直接は使わない**」／ semantic =「**用途で意味づけ**」）に照らすと、
`--spacing` も `--text-sm` も **サイズを言っているだけで用途を言っていない**。したがって Tailwind 既定は primitive。

A を採ると、思想①「UI は semantic だけを使う」は**名前では検証できなくなる**。
根拠は「値の集合を閉じた」（＝任意値禁止 lint が通る）ことだけになり、
**`p-4` と `p-7` のどちらが正しいかは誰も判定できない状態が残る**。当初の課題「AI が margin/padding を毎回発明する」は、
値の集合を閉じるだけでは止まらない（集合の中で発明できてしまう）。

### C を採らなかった理由

2 つある。

1. **必要性が 2 回証明されていない。**規約を lint で強制するのは仕組みの追加であり、
   「用途名を足したのに使われなかった」という観測がまだ 1 度も無い。手8（validate.mjs）まで待つ。
2. 🟥 **採ると手5 の前提がその場で壊れる。**C は shadcn の素の部品が持つ **spacing 132 箇所 / text サイズ 43 箇所**を
   すべて赤にする。赤を消すには部品を書き換えるしかなく、**「部品を 1 行も触らずに」という手5 の問い自体が消える。**

## 根拠（実測）

| 観測                                                             | 値                                                                                 |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |

> 射程を広げて裏を取り、結論が変わらないことを確認した。

## 影響

- 🟥 **自前 semantic 層の射程は「自作部品だけ」。**shadcn の素の部品は 175 箇所（132 + 43）を素のユーティリティで直書きしており、
  **部品を触らない限り semantic 層を使わない。**思想①の「Layout テンプレが取れる gap/padding を semantic token に限定する」は、
  **手3 で自作する Layout テンプレの内側でのみ成立する。**この限界を承知のうえでの採用（ユーザー決定）。
  → **限界そのものが手5 の観測結果になる**（「変わらなかった箇所」の一部が先に特定できている）。
- 🟨 tmp-admin は **用途名タイポを持つが Tailwind はサイズ名しか持たない**ため、B を採らないと手5 で写す先が無い。
  B は手5 の差し替えを「参照先を向け替えるだけ」にする前提でもある（手順書 D5）。
- 🟦 C（lint 強化）は**捨てたのではなく手8 送り**。「用途名を足したのに使われなかった」が観測されたら、そこが 1 回目の証明になる。
