# DR-0065: Claude Design は登録した部品を「使う」

## 背景

[段取り §5](../UI検証の位置づけと段取り.md) は手7 の結果で分岐すると定めていた。

| 答え | 帰結 |
| --- | --- |
| 🟦 使う | **往復ワークフローが成立する。**部品はコードごと移送する |
| 🟥 作り直す | **Claude Design は案出し専用に格下げ。**部品は人が手で組んで供給する |

同じ依頼文で 3 周まわし、**1 周ごとに変数を 1 つだけ動かして**測った。

## 発見

### ★ 3 周とも「使った」。しかも 1 周目は**明示していない**

1 周目の依頼文には「デザインシステムを使って」も部品名も**書いていない**（手7 D1=C の A 条件）。
それでも:

| 層 | 1 周目の判定 | 根拠 |
| --- | --- | --- |
| ④ Templates | 🟦 使った | `AppShell` に `brand` / `nav` |
| ③ Patterns | 🟦 使った | `EmptyState` |
| ② 製品層・自作 | 🟦 使った | `Section` / `Inline` / `Stack` / `Box` |
| ② 製品層・ラッパー | 🟦 使った | `Button` |
| ② 製品層・DataDisplay | 🟦 使った | `DataGrid` ＋ `StatusPill` |

**素の HTML 要素は `<span>` だけ。**`<div>` / `<button>` / `<table>` は **3 周とも 0 件。**
🟥 受け手の機械ゲートが見るのは `<button>` 1 本だけ（[DR-0059](DR-0059-receiver-generates-its-own-adherence-lint.md)）なので、
**`<div>` での迂回は検出されない。それでも 0 だった。**

### ★ 足せば足すほど使う

| | 1 周目（14 部品） | 2 周目（30 部品） | 3 周目（30 部品 ＋ 語彙） |
| --- | --- | --- | --- |
| 使った部品の**種類** | **10** | **17** | **18** |

2 周目で増えた 8 種は全部**素材層**（`Card` / `CardContent` / `Select` 一式 / `Label`）。
3 周目でさらに `Container` が増えた。**渡した部品は使われる。**

### 🟦 フラグ（分類）も越えた

**最強の証拠は `AppProviders`。**これは 30 部品に入っておらず、カードも `.d.ts` も `.prompt.md` も無い。
🟥 **3 周目に至っては `README.md` すらデザイン側に複製されていない**（[DR-0064](DR-0064-design-project-receives-runtime-only.md)）。
それでも **3 周とも最外に 1 回だけ**正しく置かれ、二重ネストは 0。
→ **conventions header（system prompt へ inline）だけで、分類は境界を越える。**

## 根拠（実測）

2026-08-02。生成物 3 本を同一の grep 群で数えた（計測器は赤テスト済み）。

```
artifacts/h7/RedmineIssueList.dc.html      1 周目
artifacts/h7/redmine-issue-list.dc.html    2 周目
artifacts/h7/RedmineIssueList-r3.dc.html   3 周目
```

判定基準は [DR-0033](DR-0033-step5-criteria-differ-per-layer.md)（層ごとに定義を変える）＋ 素の要素の数（手7 D4=B+C）。

## 影響

**観測から直接言えること**

1. ★ **段取り §5 の分岐は「使う」側に決した。往復ワークフローは成立する。**
   → **手9 は「部品をコードごと移送する」形で設計してよい。**
2. 🟦 **手2b の Storybook 投資が二重に効いた**——開発カタログとして入れたものが、
   converter の入力形式であり（[DR-0057](DR-0057-design-sync-uploads-compiled-code-not-just-html.md)）、
   さらに**忠実度の基準器**でもあった（30/30 全件 `match`）。
3. 🟦 **[DR-0002](DR-0002-verify-three-layers-not-screens.md) の見立て（画面ではなく 3 層を検証する）が正しかった。**
   測ったのは画面の出来ではなく「**どの層の部品が選ばれたか**」で、答えは層ごとに出た。

**🟥 推論（未検証）**

- 🟥 **「使う」は「正しく使う」ではない。**手7 が測ったのは**部品を選んだか**まで。
  **API を正しく使えているか**（型・必須 props・アクセシビリティ）は**手8 の lint / validate.mjs** の仕事。
- 🟥 **画面 1 種類・3 周の観測。**別の画面種（フォーム・詳細・ダッシュボード）で同じ率が出るかは**未検証。**
- 🟥 **1 周目が「明示なしで使った」のは、部品が要件に素直に対応していたからかもしれない。**
  部品が要件から遠い画面では作り直す可能性が残る。**反例を探すなら別の画面種で 1 周。**
