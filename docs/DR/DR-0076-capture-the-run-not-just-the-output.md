# DR-0076: 生成の周は「成果物」と「過程」の両方を持ち帰る

## 背景

本 repo は**周ごとに予測を先に登録し、1 変数だけ動かして数え上げる**やり方で 7 周回してきた。
これは後付けの物語を防ぐが、**予測を登録した時点で数え方（grep の対象）が予測のコピーになる**。
結果、**予測の外にあるものは「0 件」ではなく、数字の欄そのものが存在しない**——
[DR-0066](DR-0066-neither-side-lints-the-generated-output.md) の「対象 0 件で緑」と同じ形が、ゲートではなく**測定側**で起きる。

7 周目までに、**判断を動かした観測が 3 回とも装置の射程の外から来た。**

| いつ | 何が出たか | どこにあったか | 拾ったのは |
| --- | --- | --- | --- |
| r4・r5（[DR-0069](DR-0069-adding-prohibitions-to-the-header-degraded-the-output.md)） | 骨格 3 部品が消えた | 成果物の中・**面の定義の外** | 🟥 ユーザーの目視（2 周とも） |
| r7 | インラインスタイル ×2（[OBS-0013](../OBS/OBS-0013_部品があるのにインラインスタイルで組んだ.md)） | 成果物の中・**面の定義の外** | 🟥 全文を通しで読んだから |
| r7 | `.prompt.md` を読んでいた（[DR-0075](DR-0075-design-side-reads-the-design-system-directly.md)） | 🟥 **成果物の外＝生成の過程** | 🟥 ユーザーが共有したツールトレース |

3 例目は**成果物をどれだけ読んでも出てこない**。**過程を 1 度も持ち帰っていないから**である。

## 決定

**生成の周（`/design-sync` → 生成 → 数え上げ）の観測を 3 点に広げる。**

1. **過程を持ち帰る。**生成中のツールトレース（agent が何を list / read / search したか）を、
   人がスクリーンショットまたはテキストで `artifacts/h<N>/` に置く。
   🟥 **境界の向こうの操作なので人が実行する**（[DR-0001](DR-0001-repo-role-and-deliverable.md) と同じ扱い）。
2. **数え上げを grep で終えない。**登録した面の grep を回したあと、**成果物を 1 回通しで読み**、
   **面の定義の外に出たものを列挙する**。列挙が 0 件でも「0 件だった」と記録する。
3. **予測表に「予測していない箇所」の行を必ず置く。**
   [DR-0069](DR-0069-adding-prohibitions-to-the-header-degraded-the-output.md) が
   「触っていない箇所も数える」と言っているのを、**予測の様式として実行手段にする**。

## 根拠（実測）

上表の 3 例。とくに 3 例目の代償が具体的:

- **r1〜r6 の 6 周、過程を 1 度も記録していない。**→ `.prompt.md` を読む経路が
  **7 周目に生えたのか、1 周目からあったのか、永久に判定できない。**
- [DR-0064](DR-0064-design-project-receives-runtime-only.md) は**成果物側の `list_files` 3 周ぶんだけ**で
  「届くのはランタイム 3 ファイル ＋ header だけ」と結論し、それを §影響の
  **「観測から直接言えること」**の側に置いた。過程を見ていれば書けなかった。
- その推論（「届けたいなら header 本文に畳み込むしかない」）が、
  **手8 以降の選択肢を header 1 本に絞っていた**。手8d は header を 6 箇所直したが、
  🟦 **`.prompt.md` という口は、たぶんずっと開いていた。**

## 影響

**観測から直接言えること**

1. **3 例のうち 1 例は、成果物をいくら読んでも拾えない場所にあった。**装置を足さない限り再現しない。
2. **6 周ぶんの過程は失われている。**遡って取ることはできない。
3. 2 は安い（成果物 1 本を読むだけ）。1 は**人の操作が 1 手増える**。

**🟥 推論（未検証）**

- トレースを取れば「**何をきっかけに `.prompt.md` を選ぶのか**」（README 由来 / 要件由来 / 常に全部）が
  切り分けられる**はず**だが、まだ 1 周も取っていない。**8 周目で確かめる。**
- 🟥 **手段（トレース）を選んだ証拠は 1 例しかない。**
  3 例で証明されたのは「**予測の外から来る**」ことであって「トレースが常に要る」ことではない。
  → **2 回ルールの前倒しをユーザー判断で行った**（2026-08-07）。
  [PARADIGM の「具体は使い捨て」](../../CLAUDE.md)に従い、**効かなければ捨てる**。
  8 周目で「トレースから何も出なかった」なら、この決定の 1 を落として 2・3 だけ残す。
