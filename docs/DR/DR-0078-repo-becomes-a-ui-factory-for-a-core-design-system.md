# DR-0078: repo の役割は「UI 工場」— 目的は自分用コアデザインシステム、Redmine 5 画面は題材

## 背景

[DR-0001](DR-0001-repo-role-and-deliverable.md) は本 repo を「ワークフロー検証の場・成果物は決定 + PoC へ移送可能なコード」と定めていた。
2026-08-07 のユーザー判断で役割が変わり（[工場の段取り.md](../工場の段取り.md)）、同日の追加指示で**目的の主従**が確定した:

> 「自分の UI 工場としてこのリポジトリを運用していきたい」
> 「題材は Redmine の UI、これを作りながらコンポーネントを作っていく」
> 「Redmine 用のデザインを作りながらそれをコアデザインシステムとして抽象化して、自分用のスーパーセットみたいなのを作っていきたい」
> 「特にレイアウトとかもコアのコンポーネントとして整備できれば、あとは今後作るサイトは全部パズルみたいな感じで行けるんじゃないか」

## 決定

1. **本 repo は「他の開発でも使い回せる UI を作る工場」**。成果物は部品・画面・その作り方の決定。
2. **最終目的は「自分用コアデザインシステム」**——Redmine 固有の実装から抽象化した、複数リポジトリで使い回すスーパーセット。
   **Redmine の 5 画面は題材**であり、部品の需要を洗い出して抽象化の材料を供給する役。
   → [DR-0002](DR-0002-verify-three-layers-not-screens.md) の「画面は口実」は形を変えて残る——**画面も出荷物になる**が、**資産の主はコア（3 層）のまま**。
3. **レイアウトはコアに含める。**共通シェル・フィルタ帯・Layout プリミティブなどの「画面の骨格」を Redmine 固有にせず、
   コア部品として整備する（既に Layout 7 件が実在し、Polaris の Box と同型の外部先例つき——[DR-0032](DR-0032-layout-primitives-take-props-not-classname.md)・[DR-0071](DR-0071-closed-product-layer-is-viable.md)）。
4. **PoC への移送（旧・手9）は廃止する。**PoC は「規約・lint の出どころ」という参照先として残る。
5. **[DR-0001](DR-0001-repo-role-and-deliverable.md)・[DR-0002](DR-0002-verify-three-layers-not-screens.md) は superseded**（本書が置き換える）。
   移送系の残りの決定は一括 supersede しない——決定内容そのものは有効で、**出口（宛先）だけが消えた**ものが大半のため。宛先の向け直しは [DR-0081](DR-0081-poc-feedback-redirected-to-factory-conventions.md)。

## 根拠（実測）

- ユーザー判断 2 回（2026-08-07 の役割転換＝[工場の段取り.md](../工場の段取り.md)、同日の本指示＝目的の主従・コアの範囲）。
- **工程0 Q1 の棚卸し**: 現役（superseded 除く）の DR のうち、**PoC の存在・移送を前提にしている DR は 22 件**
  （0001 / 0002 / 0003 / 0005 / 0008 / 0009 / 0010 / 0014 / 0016 / 0017 / 0019 / 0023 / 0024 / 0025 / 0046 / 0047 / 0048 / 0057 / 0062 / 0065 / 0066 / 0068）。
  うち**決定の本体まで崩れるのは 0001・0002・0003 の 3 件だけ**で、残り 19 件は観測・決定は有効なまま「PoC という宛先」を失っている
  （詳細は [実行記録 §工程0](../実行記録.md)）。
- 工場化の技術的根拠（Vite 化の実測 4 件・持ち越し資産の一覧）は [工場の段取り.md](../工場の段取り.md) §1 が正本。

## 影響

**観測から直接言えること**

1. DR-0001・0002・0003 が superseded になる（0003 の置き換えは [DR-0080](DR-0080-strict-pins-stay-for-reproducibility.md)）。
2. 旧地図（[UI検証の位置づけと段取り.md](../UI検証の位置づけと段取り.md)）は検証の記録として凍結、地図は [工場の段取り.md](../工場の段取り.md) に一本化。
3. 作業単位の語彙が `手N` → `工程N` に変わる（`.claude/trace.config.mjs` に追加済み。旧文書の `手N` はそのまま）。

**🟥 推論（未検証）**

- **「コアが揃えば今後のサイトはパズルのように組めるだけ」はまだ仮説。**検証されるのは
  ① 工程3〜8 で Redmine 5 画面がコア部品の組み合わせでどこまで書けるか、
  ② 2 つ目の使い回し先が現れたとき、Redmine 固有物とコアの境界が実際に切れているか——の 2 段。
  🟥 **本 repo はまだ「Redmine 固有 / コア」の判定規則を持っていない**（いまの判定規則
  [製品層の部品設計.md](../製品層の部品設計.md) は素材層/製品層の境界を見るもので、汎用/固有の軸は別）。
  工程3 以降で固有物が最初に現れたときに立てる。
