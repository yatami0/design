## 2. 下層（素材層）の共通性質 — className は「設計として」開いている

調査済み 5 本のうち、下層に相当する層を持つものは**全部が `className` を受ける**。しかも**偶然ではなく設計**:

- **Radix**: "All components and their parts accept a `className` prop. This class will be passed through to the DOM element."（[Styling guide](https://www.radix-ui.com/primitives/docs/guides/styling)・2026-08-02）。仕組みとしても `@radix-ui/react-primitive` が**全 DOM props を無フィルタで spread** するので、開いていることが層の実装そのもの
- **理由も明文**: "Radix Primitives are unstyled—and compatible with any styling solution—**giving you complete control over styling**."（同上）。**Dialog の Overlay が viewport を覆うことすら既定で付けない**（"You are in control of all aspects of styling, including functional styles"）
- **Base UI**: ネイティブ `className` を**一度 Omit してから関数形で置き換える**——`className?: string | ((state: State) => string)`（[types.ts](https://github.com/mui/base-ui)・2026-08-02）。開くだけでなく**状態を styling に渡す口**として拡張している
- **shadcn/ui**: 全部品が `className` を受けて `cn()` で merge。ただし理由は Radix と違い **Open Code**（"The top layer of your component code is open for modification"・[docs](https://ui.shadcn.com/docs)・2026-08-02）——**上書きさせるためではなく、コードごと所有させるため**

★ **Q1 に効く事実**: 下層が `className` を開けているのは「見た目を決めない層だから」という仮説（手順書 §2.9）は**裏が取れた**。Radix の定義文がそのまま「**見た目の管轄権は上の層にある**」と言っている。

## 3. 上層（製品層）の逃げ道 — 5 つの型が観測された

| 型 | 実例 | 中身 |
| --- | --- | --- |
| **(a) 全開＋コード所有** | shadcn/ui | className も受けるし、そもそも**コードを copy して直接編集**が本道。"This is not a component library. It is how you build your component library." |
| **(b) 縮小して受け、限界で降ろす** | Radix Themes | "The components in Radix Themes are **relatively closed**—they come with a set of styles that aren't always easily overridden." className/style は受けるが、"if you find yourself needing to override a lot of styles… **Create your own component using lower-level building blocks**"（[Themes Styling](https://www.radix-ui.com/themes/docs/overview/styling)・2026-08-02）——**逃げ道の出口は「下層で自作」**|
| **(c) 型付き逃げ道を開けて、後から閉じた** | Primer | `sx` を「抽象を漏らさない逃げ道」として導入（ADR-005: "Avoids leaky abstractions"）→ **ランタイムコストを理由に v38 で完全廃止**（"The `sx` prop is no longer supported."）。現在は className ＋ CSS Modules に一本化 |
| **(d) 逃げ道を正規 API に昇格** | Material UI | `sx` は "the best option for adding style overrides to a single instance" ——**escape hatch ではなく第一選択肢**。内部要素へも `slots`/`slotProps` で公式に到達させる |
| **(e) 閉じる（受けない）** | 🟥 Polaris（調査中）・React Spectrum（調査中） | 確定は再走の結果待ち |

🟨 **観測のまとめ（事実の範囲で）**: 調査済み 5 本に「**製品層で `className` を型から消した**」ものは無い。閉じ方の最有力候補（Polaris・Spectrum）は調査中。ただし **(b)(c) の 2 例は「開けた逃げ道は管理コストを生む」ことの実測**になっている——Primer は廃止に major version 1 つ（v37→v38・自動変換ツール付き）を費やし、Radix Themes は「多用したら降りろ」という**運用ルールで縛る**しかなくなっている。

## 4. 「単純な API は上層で作る」は公式パターンだった

- **Radix**: 各部品 docs に **Custom APIs** 節があり、"**Create your own API by abstracting the primitive parts into your own component.**"（[Select docs](https://www.radix-ui.com/primitives/docs/components/select)・2026-08-02）——parts を包んで **props を圧縮した部品を利用者が作る**実装例まで載る
- **shadcn/ui**: data-table は部品ではなく**ガイド**: "So instead of a data-table component, I thought it would be more helpful to provide a guide on how to build your own."（[Data Table docs](https://ui.shadcn.com/docs/components/data-table)・2026-08-02）——**表の抽象化は利用者の責務**と明言
- **Primer**: 部品の上の層（UI Patterns）は**コードを持たない文書層**（"Design guidelines covering common user workflows"）
- **Carbon**: 同じく patterns は "reusable combinations of components and templates" の**ガイダンス層**

★ **Q1 に効く事実**: 我々の「素材層を組み合わせるための抽象的な製品層」は、Radix の Custom APIs・shadcn の data-table ガイドが**利用者に作らせようとしているものと同じ位置**にある。**上流 2 つとも「この層は配布物に含めない。使う側が作る」と設計している**——我々はその「使う側」。

## 5. 依存の型を公開 API にする扱い（Q6）

| DS | 形 | 含意 |
| --- | --- | --- |
| shadcn/ui | **素通し**。`React.ComponentProps<typeof SelectPrimitive.Trigger> & { size?: … }` に**独自 props だけ交差型で足す**。data-table では `ColumnDef` を利用者が直接書く | 型の出どころ（Radix・TanStack）を隠さない。**コード所有モデルだから成立**——利用者は型の行き先を編集できる |
| Material UI | **上層の公開面から選別して再輸出**: `export type { ClickAwayListenerProps } from '@mui/base/…'`（v5）・`export { SxProps } from '@mui/system'`（現行） | **利用者に下層パッケージを import させない**ための出し直し。窓口 1 本の型版 |
| Radix | 依存がほぼ無い。part ごとの `*Props` を**ローカル定義**（`type PrimitiveButtonProps = React.ComponentPropsWithoutRef<typeof Primitive.button>`）して全公開 | 型も自分の名前で出す |
| Primer | 明示的再輸出は無し。ただし hook の公開型シグネチャに `@primer/behaviors` の型が**構造的にリーク**。ADR-005: "We have had issues with exporting types, we can increase confidence by **keeping the exported types close to what we author**." | **「自分で書いた型に近いものだけ出す」を教訓として明文化**している |
| Carbon | `@carbon/react/icons` が `@carbon/icons-react` を **getter で透過再輸出**。自前 Props 型は `export type` で全公開 | 利用者は依存を直接 import しない |
| 我々 | 🟥 `DataGrid.columns: ColumnDef<TData, TValue>[]` を**素通し**。`cell: (ctx) => JSX` という**任意 JSX の口も一緒に**公開された（[DR-0060](DR/DR-0060-vocabulary-leaks-from-four-surfaces.md) 面③） | 手8 の 6 周で**語彙表の外に出た逸脱は全部ここから**（実行記録 §手8c H8C-01） |

★ **Q6 に効く事実**: 素通し（shadcn 型）は**コード所有モデルとセット**で成立している。パッケージ境界を保つ DS（MUI・Carbon・Primer）は**依存の型を自分の公開面から出し直すか、自分の型だけを出す**。我々は**パッケージ境界型の配布（`/design-sync` の bundle）なのに素通し**をしている——型のモデルと配布のモデルが食い違っている。

## 6. 境界の定義文 — 各 DS は二層をどう言葉で切っているか

| DS | 下層の責務 | 上層の責務 | 出典 |
| --- | --- | --- | --- |
| Radix | "unstyled … complete control over styling"（見た目を決めない） | Themes = "relatively closed … a set of styles" | [Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction)・[Themes Styling](https://www.radix-ui.com/themes/docs/overview/styling)（2026-08-02） |
| Base UI ↔ MUI | "functionality and structure, while designers and developers are responsible for the visuals" | Material UI = 速度優先の pre-styled（"use Material UI for rapid prototyping, and then switch to MUI Base when you need more customization"） | [Introducing Base UI](https://mui.com/blog/introducing-base-ui/)（MUI 本人・2026-08-02 取得） |
| shadcn/ui | ui = "single-file primitives" | block = "complex components with multiple files"・base = "entire design systems" | [registry-item-json](https://ui.shadcn.com/docs/registry/registry-item-json)（2026-08-02） |
| Carbon | `@carbon/styles`＝言語非依存の共有スタイル層 | components（1 UI 問題）→ patterns（目的・フロー） | [patterns/overview](https://carbondesignsystem.com/patterns/overview/)（2026-08-02） |
| Primer | behaviors（DOM 挙動 util）＋ primitives（トークン） | 部品 → UI Patterns（文書） | [primer.style](https://primer.style/product/components/)（2026-08-02） |

🟨 **切り口は 1 つではない**: Radix/Base UI は「**見た目を決めるか決めないか**」、shadcn は「**ファイル数・粒度**」、Carbon/Primer は「**単機能か、目的をまたぐ組み合わせか**」。ただし調査済み 5 本のうち headless 二層を持つ 2 本（Radix・Base UI）は**どちらも「見た目の管轄権」で切っている**。
