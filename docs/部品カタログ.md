## 表2. 分類できなかった・迷ったもの（Q4 の答え）

| 部品 | なぜ入らないか | 対処案 |
|---|---|---|
| **Direction** | **部品ではない。**RTL/LTR の方向をツリーに配るコンテキスト提供者。9 カテゴリは「画面に出る部品」の分類なので、そもそも対象外 | 🟦 分類しない。**思想に「部品でないもの（Provider / Context）」の置き場が無い**ことが露出した |
| **Marker** | 用途が公式一覧から読み取れず未調査 | 手3 で使うことになったら調べる。今は分類しない |
| Accordion / Collapsible | 「開閉する」が overlay ではない。思想の Layout（Box/Stack/Grid/Container/Spacer/Card/Section）にも Overlay（重なり・開閉）にも綺麗に入らない | 🟨 **Overlay の定義が「重なり *かつ* 開閉」で 2 条件を AND しているのが原因。**開閉だけする部品（disclosure）の居場所が無い。→ 思想への指摘（下記） |
| Field | ラベル+説明+エラーの配置構造。Layout に入れたが、思想の Layout は「汎用の配置」で、Field は「フォーム専用の配置」 | 🟨 Layout のまま。備考に用途を書く |
| Command / Combobox | 複数カテゴリの合成（Overlay + Selection + Navigation） | 🟨 **主たる役割 1 つを選ぶ**という規則どおり暫定を置いた。合成部品であることを備考に残す |
| Carousel / Item / Toggle | 2 カテゴリのどちらとも読める | 🟨 暫定を置き、備考に対抗案を書いた |
| Attachment / Bubble / Message / Message Scroller | **AI チャット UI 向けの新カテゴリ。**思想が作られた時点に存在しなかった部品群 | 🟨 暫定で DataDisplay / Layout に置いた。今回の題材（管理画面）では使わない |

### 🟦 思想への指摘（書き換えはしない。判断はユーザー）

1. **「部品でないもの」の置き場が無い。**`Direction` のような Provider / Context は 9 カテゴリのどれにも属さないが、実在し、アプリに配線が要る。`Tooltip` も `TooltipProvider` を要求する。**役割分類とは別の軸（配線が要るか）が必要かもしれない。**
2. **Overlay の定義が 2 条件の AND になっている。**「重なり・開閉」としているため、**開閉するが重ならない**部品（Accordion / Collapsible）が宙に浮く。思想が状態を分類軸から追い出した趣旨に照らすと、Overlay は「重なり」だけで定義し、開閉は `stateful` フラグで表すほうが一貫する。
3. **フラグに `provider` を足す余地がある。**`behaviorHook` は「振る舞いを担う hook」だが、`TooltipProvider` のように **hook ではなく Provider で配線するもの**が表せない。

## 表5. 任意値の分類（Q2 の答え）— 手5 の判定に直結

`tailwindcss/no-arbitrary-value` の検出 **24 件**を、**トークン差し替えに追従するか**で分けた。

| 分類 | 件数 | 意味 | 手5 への影響 |
|---|---|---|---|
| **(A) トークンのみで構成** | 4 | `var()` と Tailwind 関数だけで組まれ、生値を含まない | 🟦 **追従する。**実質トークン内 |
| **(B) トークン + 生値の混合** | 6 | `min(var(--radius-md),10px)` のように上限・下限に生値が混ざる | 🟨 **部分的に追従。**生値部分は固定される |
| **(C) 純粋な生値** | 8 | `text-[0.8rem]` `rounded-[4px]` `min-w-[96px]` など | 🟥 **追従しない。**トークンを差し替えても変わらない |
| **(D) 値ではない** | 6 | `transition-[width]` `grid-cols-[1fr_auto]` — **CSS プロパティ名やグリッド定義**であって、デザイン値ではない | 🟦 影響なし。**ルールの過剰検知** |

**(A) トークンのみ — 4 件**
- `button.tsx` `hover:bg-[color-mix(in oklch,var(--secondary),var(--foreground) 5%)]`
- `sidebar.tsx` `w-[calc(var(--sidebar-width-icon)+(--spacing(4)))]`
- `sidebar.tsx` `left-[calc(var(--sidebar-width)*-1)]`
- `sidebar.tsx` `right-[calc(var(--sidebar-width)*-1)]`

**(B) トークン + 生値 — 6 件**

- `select.tsx` `data-[size=sm]:rounded-[min(var(--radius-md),10px)]`
- `sidebar.tsx` `w-[calc(var(--sidebar-width-icon)+(--spacing(4))+2px)]`
- `sidebar.tsx` `shadow-[0 0 0 1px var(--sidebar-border)]` / `hover:shadow-[0 0 0 1px var(--sidebar-accent)]`

**(C) 純粋な生値 — 8 件**
- `badge.tsx` `focus-visible:ring-[3px]`
- `button.tsx` `text-[0.8rem]`
- `checkbox.tsx` `rounded-[4px]`
- `dialog.tsx` `max-w-[calc(100%-2rem)]`
- `dropdown-menu.tsx` `min-w-[96px]`
- `sidebar.tsx` `after:w-[2px]`
- `tooltip.tsx` `translate-y-[calc(-50% - 2px)]` / `rounded-[2px]`

**(D) 値ではない — 6 件**
- `card.tsx` `grid-cols-[1fr_auto]` / `grid-rows-[auto_auto]`
- `sidebar.tsx` `transition-[width]` / `transition-[left,right,width]` / `transition-[margin,opacity]` / `transition-[width,height,padding]`

> 🟥 **これが手1 で一番重い発見。**思想①は「AI が margin/padding を発明するのを止める」ためにトークンを置いたが、
> **shadcn 自身が発明している**（(C) の 8 件）。`text-[0.8rem]` や `rounded-[4px]` は、
> トークンを差し替えても変わらない＝**「箱を触らずテーマだけ変える」が最初から部分的にしか成立しない。**
>
> 🟦 同時に、**ルールの側にも粒度の問題がある**（(D) の 6 件）。`transition-[width]` は
> プロパティ名の指定であって値の発明ではない。**`no-arbitrary-value` は「値の発明」と「構文上の指定」を区別しない。**
