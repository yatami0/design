## 1. 44px はどこから来たか

### 出どころは apple base であって tmp-admin ではない

`~/git/CC-Skills/.claude/skills/web-design-mock/references/apple/apple.md`（実測）:

| 行 | 記述 |
|---|---|
| 63 | \| **タッチターゲット / コントラスト** \| 公式 a11y 規定(44pt, 4.5:1 / 3:1) \| 公式値・**不可侵の下限** \| |
| 149 | `--touch-min: 44px;   /* 最小タッチターゲット 44×44pt */` |
| 193 | §4.5 アクセシビリティ **[公式・不可侵]** — タッチターゲット **44×44px 以上**（`--touch-min`） |

**`apple.md` は自分の値を「公式」と「導出」に分けている。**
色・タイポ・タッチターゲット・コントラストは「公式値」、spacing・角丸・影・ブレークポイントは「導出（Apple は非公開）」。
44px は**公式側に置かれているから不可侵**と宣言されている——つまり **根拠は「Apple がそう言っているから」**であって、
計測や WCAG からの導出ではない。

### tmp-admin が実際に規定しているのは 1 箇所だけ

`~/git/CC-Skills/web-design-mock/_philosophies/aux-admin/aux-admin.md`（実測）:

```
§4  レイアウト規約(apple base へのデルタ)
    base の グリッド/ブレークポイント/余白リズム/ a11y(44px・4.5:1/3:1) は apple.md §4 を継承。

§4.2 サイドバー(on-dark / V5)
    - nav-item は min-height `--touch-min`、…
```

> 🟥 **`--touch-min` を名指しで適用しているのは `nav-item` の `min-height` だけ。**
> 「すべてのコントロールが 44px 以上」という規定は**どこにも書かれていない**。
> **本 repo が「継承」を「全コントロールへの下限」と読み替えていた**——これは [DR-0023](DR/DR-0023-real-conflict-is-touch-target.md) の訂正にあたる。

### nova の `h-8` はどこから来たか

`src/components/ui/button.tsx`（実測）。**根拠の記述は無い**——プリセットの意匠としてそう書かれているだけ。

| size | クラス | 実効高さ |
|---|---|---|
| `xs` | `h-6` | **24px** |
| `sm` | `h-7` | **28px** |
| `default` | `h-8` | **32px** |
| `lg` | `h-9` | **36px** |
| `icon` | `size-8` | 32×32px |
| `icon-lg` | `size-9` | 36×36px |

## 2. 世の中の「下限」は 1 つではない

| 出所 | 値 | 位置づけ | 適合レベル |
|---|---|---|---|
| **WCAG 2.2 SC 2.5.8** Target Size (Minimum) | **24×24 CSS px** | 🟦 **これが実際の法規適合ライン** | **AA**（＋間隔例外あり） |
| **WCAG 2.1 SC 2.5.5** Target Size (Enhanced) | 44×44 CSS px | 望ましい水準 | **AAA** |
| **Apple HIG** | 44×44 pt | プラットフォーム指針。**「見た目」ではなく「タップできる面積」**を言っている | — |
| **Material Design** | 48×48 dp | プラットフォーム指針。Apple より広い | — |

### これを nova の実測値に当てると

| size | 高さ | WCAG 2.5.8（AA・24px） | WCAG 2.5.5（AAA・44px） | Apple（44px） |
|---|---|---|---|---|
| `xs` 24px | 24 | 🟨 **ぎりぎり適合** | ❌ | ❌ |
| `sm` 28px | 28 | 🟦 適合 | ❌ | ❌ |
| **`default` 32px** | 32 | 🟦 **適合** | ❌ | ❌ |
| `lg` 36px | 36 | 🟦 適合 | ❌ | ❌ |

> 🟦 **nova の既定（32px）は WCAG の AA を満たしている。**満たしていないのは **AAA と Apple の指針**。
> [DR-0023](DR/DR-0023-real-conflict-is-touch-target.md) の「**下限割れ**」という表現は、**apple.md の下限に対しては正しいが、WCAG の適合ラインに対しては誤り**。

### ⚠ 単位の罠

Apple の 44pt は **iOS の論理ポイント**であり、Web に写すときは **44 CSS px** と読むのが通例。
`apple.md` は `--touch-min: 44px` と書いており、**この翻訳は正しい**。
（CSS の `pt` 単位として読むと 1pt = 4/3px なので 58.67px になるが、それは別の単位の話。ネット上の「44pt = 59px」という記述はこの読み替え。）

## 3. 選択肢は 3 つではなく、少なくとも 7 つある

**核心**: Apple 自身が「タップできる面積であって見た目ではない」と言っている。
**見た目のサイズと当たり判定のサイズは分離できる。**

| # | 案 | 見た目 | 当たり判定 | 素材層を触るか | 密度への影響 |
|---|---|---|---|---|---|
| **A** | 見た目ごと 44px にする | 44px | 44px | 🟥 触る（製品層ラッパーなら不要） | 🟥 **nova の高密度が壊れる** |
| **B** | 32px のまま受け入れる | 32px | 32px | 🟦 触らない | 🟦 無し |
| **C** | 用途で使い分ける（一覧内は 32、主要操作は 44） | 混在 | 混在 | 🟦 触らない | 🟨 判断が場面ごとに要る |
| **D** 🆕 | **当たり判定だけ広げる**（`::after` + `inset: -6px`） | **32px のまま** | **44px** | 🟦 **触らない**（外から CSS） | 🟦 **無し** |
| **E** 🆕 | **WCAG 2.5.8 の間隔例外を使う**（24px 円が交差しなければ適合） | 32px | 32px + 間隔 | 🟦 触らない | 🟨 レイアウト側に制約 |
| **F** 🆕 | **ポインタ種別で分岐**（`@media (pointer: coarse)` のときだけ拡張） | 環境依存 | 環境依存 | 🟦 触らない | 🟦 **マウス環境では無し** |
| **G** 🆕 | **制御の高さを semantic token にする**（`--control-height-*` / 密度モード） | トークン次第 | トークン次第 | 🟦 触らない（[調査1 §3](デザイントークン設計.md) の方式） | 🟦 **切り替えられる** |

### D の実装（一次情報の技法）

```css
.control { position: relative; }
@media (pointer: coarse) {
  .control::after { content: ''; position: absolute; inset: -6px; }
}
```

- 疑似要素は不可視。**見た目は 1px も変わらず、当たり判定だけ 32px → 44px になる**（上下左右 6px ずつ）。
- `@media (pointer: coarse)` を掛けると**タッチ環境でだけ効く**（＝ F との組み合わせ）。
- 🟦 **D1=(c)（既定値ラッパー）が確定しているので、これは製品層のラッパーに置ける。**

### G が調査1 と接続する

[調査1 §3](デザイントークン設計.md) で、**部品を触らずに component token を向け替える方式**（レイヤ外の `[data-slot=…]` 上書き）が実測で成立した。
**同じ方式で「制御の高さ」をトークン化できるなら、44px と 32px は「対立」ではなく「トークンの値の選択」になる。**

> 🟨 ただし `h-8` は **`--card-spacing` と違って CSS 変数になっていない**（Tailwind ユーティリティの直書き）。
> **G を採るには、まず製品層のラッパーで `h-(--control-height)` の形に置き換える必要がある**——これは素材層ではなく製品層の作業。

## 5. 🟦 思想への指摘（書き換えはしない。判断はユーザー）

[部品カタログ の指摘 1〜3](部品カタログ.md) に続く 4 件目。

4. **`apple.md` の「不可侵」は、適用範囲を伴っていない。**
   「44×44px 以上」とだけ書かれ、**何に適用するか**（全コントロールか／タッチ操作するものだけか／nav-item だけか）が規定されていない。
   tmp-admin は nav-item にしか適用しておらず、**継承した側で範囲が広がったのか狭まったのかが読めない**。
   → **「不可侵」は値の話であって範囲の話ではない**と読むなら、範囲は本 repo が決めてよいことになる。
