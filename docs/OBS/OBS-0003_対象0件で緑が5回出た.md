# OBS-0003: 「対象 0 件で緑」が 5 回出た

> 凡例：🟦 確定／根拠あり ・ 🟨 暫定／裁量 ・ 🟥 未確認・要本人確認

## 0. 一行サマリ【起票時必須】

同じ型の事故が**手0 から手4 まで 5 回**出た。**機械ゲートは「何を検査していないか」を報告しない。**

## 1. きっかけ（何を見て・何に引っかかったか）【起票時必須】

手4 の H4-01 で、新設ディレクトリ（`src/patterns/` `src/templates/`）に赤テストを置いたら
**lint が exit 0 で 1 件も出さなかった**（[DR-0040](../DR/DR-0040-frame-leaks-when-a-layer-is-added.md)）。
「またこれか」と思った時点で、**同じ型の事故を数えたことがなかった**ことに気づいた。

## 2. 経緯と今の理解【起票時必須】

数えたら **5 回**あった。

| # | 事例 | 手 | 何が緑だったか |
|---|---|---|---|
| 1 | PoC で lint が対象 0 件で緑（前例。本 repo の規律の出どころ） | — | 検査対象が 1 件も無いのに成功扱い |
| 2 | Tailwind が `docs/**.md` を走査していた（[DR-0021](../DR/DR-0021-tailwind-scans-docs-markdown.md)） | 手2 | **逆方向の漏れ**。射程が広すぎて文章中のクラス名を本番 CSS に生成 |
| 3 | `.storybook/**` がどのゲートの射程にも入っていなかった（[DR-0025](../DR/DR-0025-storybook-init-is-not-selectable.md)） | 手2b | typecheck 対象外・lint は parse error だけ |
| 4 | `--spacing: initial` で素材 18 部品の余白 128 箇所が死んでもビルドは緑（[DR-0028](../DR/DR-0028-token-frame-is-not-closed.md)） | 手3 | **CSS は存在しないクラスを黙って無視する** |
| 5 | ③ 層が lint の射程外（DR-0040） | 手4 | `files` をディレクトリ名で絞っていたため |

**共通する構造**: どのゲートも「**検査した結果、問題が無かった**」と「**そもそも検査していない**」を**同じ緑で表す**。

## 3. 知識の結びつき ★主目的

- **既に持っていた知識・経験**: CLAUDE.md に「**緑を信用しない。**赤テストで gate が発火することを確かめる」と書かれており、
  PoC で実際に事故があった。**規律としては最初から持っていた。**
- **今回新しく得た・繋がった知識**: 事例 2 と 4 は**規律が想定していた形と違った**。
  - 事例 2 は**射程が狭すぎる**のではなく**広すぎる**漏れ。
  - 事例 4 は lint ではなく **CSS の仕様**（存在しないクラスを無視する）が原因で、赤テストの対象ですらなかった。
- **結びついて生まれた気づき（一般則）**:
  > **「緑を信用しない」は「赤テストを書く」だけでは足りない。**
  > 確かめるべきは 3 つ: ①**射程に入っているか**（狭すぎないか）②**射程が広すぎないか** ③**壊れたときに赤くなる仕組みがあるか**。
  > 事例 4 のように**壊れても赤くなりようがない**ものは、赤テストでは捕まらない。

🟦 **効いた運用**: 手2b の H2B-03 と手4 の H4-01 は、どちらも「**書く前に射程を確かめる**」ステップを手順に置いていた。
両方とも**書いたコードを検査し直す事態を避けられた**。

## 4. 結論と保留

- **今の結論**: 🟦 **新しいディレクトリ／新しい層を作る手には、必ず「射程テスト」ステップを置く。**手2b・手4 で 2 回効いた。
- **保留・未確認**:
  - 🟨 **仕組み化するかは未決。**必要性は 2 回証明された（手2b・手4）が、
    「手順書テンプレートに常設ステップとして足す」のか「その都度書く」のかを決めていない → 手9 で判断。
  - 🟥 **事例 4 の型（壊れても赤くならない）への対処は未決。**トークンを消しても緑になる問題は、
    赤テストでは捕まらない。**手5 の判定で同じ罠がある。**
- **この結論が変わる条件**: 6 回目が別の型で出たら、分類をやり直す。

## 5. 却下した代替案

| 案 | 内容 | 却下理由 |
|---|---|---|
| ゲートに「検査対象件数」を出させる | 0 件なら警告 | 🟨 **却下ではなく未検討。**eslint は `--max-warnings` 等はあるが「対象 0 件で失敗」の直接の仕組みが無い。手9 で調べる |
| `files` を絞らず `ignores` だけで運用 | 全体に張って素材層だけ外す | 🟨 **有力だが副作用未検証**（`src/lib/**` や設定ファイルを巻き込む）。手5 以降で検討 |
