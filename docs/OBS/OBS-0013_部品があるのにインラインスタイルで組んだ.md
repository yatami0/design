# OBS-0013: 部品があるのにインラインスタイルで組んだ面をどう閉じるか

> 凡例：🟦 確定／根拠あり ・ 🟨 暫定／裁量 ・ 🟥 未確認・要本人確認

## 0. 一行サマリ【起票時必須】

7 周目で**クラスの逸脱は 0 になった**が、代わりに `<div style="display:flex;flex-direction:column">` が **2 箇所**出た。
`Stack` があるのに使われなかった——**禁止も語彙も効かない出口（インラインスタイル）**をどう扱うか。

## 1. きっかけ（何を見て・何に引っかかったか）【起票時必須】

7 周目の生成物 `Redmine チケット一覧.dc.html`（プロジェクト `89a4410e-3876-41ad-a7c0-452e190d095f`）に、
`Label` と `Select` を縦に並べる箇所が 2 つあり、どちらもこう書かれていた:

```html
<div class="gap-stack-sm" style="display:flex;flex-direction:column">
```

- 🟦 `gap-stack-sm` は**宣言語彙の内**（conventions header の語彙表にある）
- 🟥 `style="display:flex;flex-direction:column"` は**語彙の外**
- 🟦 **`Stack gap="sm"` で書ける。**部品は存在し、カードにも並んでいる（31 部品のうちの 1 つ）

同じ周で、[DR-0060](../DR/DR-0060-vocabulary-leaks-from-four-surfaces.md) の 4 面（素材層の `className` /
`Box` の `className` / 列の任意 JSX / `<style>` への生 CSS）は**全部 0 になった**。
**逸脱が消えたのではなく、出口が移った**ように見える。

## 2. 経緯と今の理解【起票時必須・「わからない」でもよい】

**問い**: 語彙の外へ出る口を 1 つ塞ぐと、別の口から出るのか。それとも今回はたまたまか。

**今の理解（🟨 暫定）**:

- conventions header の禁止文は**数値の段**（`p-4` / `gap-7`）と**パレット色**（`text-gray-600`）だけを止めている。
  🟥 **インラインスタイルはどこでも禁止していない。**「書いてよい」と読める余地がある
- header は `Stack` を「takes children」の一覧に載せているが、
  🟥 **「縦に並べたいときは `Stack`」という書き方は教えていない**（Layout プリミティブの props 表はあるが、用途からの引き当てが無い）
- [DR-0063](../DR/DR-0063-forbidding-without-an-alternative-fails.md)（禁止だけでは破られ、代替語彙を与えると守られた）に照らすと、
  今回は**代替（`Stack`）は在るのに選ばれなかった**ので、DR-0063 とは形が違う。**「在る」と「引き当てられる」は別**かもしれない
- 🟥 [DR-0069](../DR/DR-0069-adding-prohibitions-to-the-header-degraded-the-output.md) があるので、
  **「インラインスタイル禁止」を header に足すのは安全ではない。**禁止を 1 つ足すと触っていない箇所が壊れた実測がある

**何がわかれば解けそうか**:

1. 8 周目で**何も変えずに**同じ形が出るか（1/1 周なのか、再現するのか）。
   🟦 [DR-0070](../DR/DR-0070-product-layer-boundary-rule.md) の判定規則①は「**同じ場所から 2 回以上出たか**」なので、
   **2 回目が出るまでは部品も規約も動かさない**のが本 repo の規律に沿う
2. 出るとして、打ち手が「header に 1 文（禁止ではなく**引き当て方**）」なのか「`Stack` の `.prompt.md` を厚くする」なのか。
   🆕 [DR-0075](../DR/DR-0075-design-side-reads-the-design-system-directly.md) で
   **`.prompt.md` が agent に届く**と分かったので、**header を触らずに部品側で教える**選択肢が新しく増えている

## 3. 知識の結びつき ★主目的【棚卸しで埋める。insight は起票時から】

- 既に持っていた知識・経験：🟥 要本人確認
- 今回新しく得た・繋がった知識：🟥 要本人確認
- 結びついて生まれた気づき（できれば 1 行の一般則まで）：🟥 要本人確認

🟨 **Claude 側の仮説（本人確認前・確定として扱わない）**:
「逸脱を数える面」を**クラス名の集合**で定義してきたので、**クラスを使わない逸脱**（インラインスタイル・
素の DOM 要素）が面の外側に落ちていた可能性がある。DR-0060 の 4 面はすべてクラスか生 CSS で定義されている。

## 4. 結論と保留

- **今の結論**：🟨 **まだ何もしない。**実測 1/6+1 周。DR-0070 の規則①（2 回）で不成立
- **保留・未確認**：🟥 再現するか。🟥 打ち手を header に置くか `.prompt.md` に置くか
- **この結論が変わる条件**：8 周目で同じ形が出たら（2 回目）、規則①が成立して打ち手の検討に入る

## 5. 却下した代替案【任意】

| 案 | 内容 | 却下理由 |
|---|---|---|
| header に「インラインスタイル禁止」を足す | 禁止文を 1 行追加 | 🟥 **DR-0069 の再演リスク。**1 回しか出ていない逸脱のために、効いている header を触る取引は割に合わない |
| `Stack` を使わせる lint 規則を足す | 受け手側 `_adherence.oxlintrc.json` に規則を期待 | 🟥 規則は `.d.ts` から自動生成され（DR-0059）、**こちらから書けない。**そもそも oxlint 側が設定を読めていない（DR-0066） |
