# OBS-0021: 面①「描画された」は、その部品が描かれたことを見ていない

> 凡例：🟦 確定／根拠あり ・ 🟨 暫定／裁量 ・ 🟥 未確認・要本人確認

## 0. 一行サマリ【起票時必須】

**面① の判定は「canvas ＋ portal に 0 でない大きさの要素が 1 つ以上あるか」**（部品1 D11=B）。
🟥 **どの部品が描かれたかは見ていない**ので、**部品本体が 1 要素も出ていなくても、
同じ story の中の別のもの（トリガのボタン等）が描かれていれば緑になる。**

## 1. きっかけ（何を見て・何に引っかかったか）【起票時必須】

[部品5](../手順/部品5_判定の保留と描かれていない状態.md) C5-05 で `Sidebar` をモバイル幅（320px）で描いた。

**実測**（2026-08-09）:

| 状態 | `[data-slot="sidebar"]` の数 | 面① |
| --- | --- | --- |
| デスクトップ（1200px） | 🟦 **1** | 🟦 緑 |
| 🟥 **モバイル（320px）・開く前** | 🟥 **0** | 🟥 **緑** |
| モバイル・トリガを押した後 | 🟦 **1**（portal・`data-mobile="true"`） | 🟦 緑 |

🟥 **`Sidebar` は `openMobile` の初期値が `false` で、外から開く prop を持たない**——
**モバイルでは、トリガを押すまで部品が DOM を 1 つも持たない。**
**それでも面① は `SidebarTrigger` のボタンを見て緑を返す。**

## 2. 経緯と今の理解【起票時必須・「わからない」でもよい】

- 🟦 **面① の現在の定義には理由がある**（[完成バー §2](../部品の完成バー.md)）——
  - `#storybook-root` だけを見ると **`Dialog/Open`（中身は portal）を落とす**
  - `textContent` で見ると **`Spacer` / `Separator`（文字を持たない）を落とす**
  - → **「canvas ＋ portal に大きさを持つ要素が 1 つ以上」**に落ち着いた
- 🟥 **この定義は「何かが描かれた」しか言えない。**
  ★★ **これは 3 つ目の緑の形**——
  - 「**対象 0 件で緑**」（検体が存在しない・通算 17 例）
  - 「**判定の保留で緑**」（[DR-0098](../DR/DR-0098-incomplete-was-counted-as-green.md)・対象は在るが機械が答えない）
  - 🆕 「**別のものが描かれているので緑**」（**対象は無いが、隣が在る**）
- 🟨 **どこまで機械で要求できるかが分からない。**
  「その部品が描かれた」を機械が言うには、**story と部品の対応**が要る——
  🟦 **材料はある**（`meta.component` ／ `title` の階層 ／ `data-slot`）が、🟥 **どれも 1 対 1 ではない**
  （`Sidebar` の story は `SidebarProvider` / `SidebarInset` / `SidebarTrigger` も同時に描く）

## 3. 知識の結びつき（本人の頭の中で何と繋がったか）

## 4. 判断が変わる条件

- 🟨 **`data-slot` を面① の検体にする案が現実的か**——**[DR-0099](../DR/DR-0099-the-blind-spot-list-must-be-machine-derived.md) の静的側は既に
  素材層の `data-slot` を一覧の正本にしている**ので、**同じ引き方が面① にも使える見込み**（🟥 未検証）
- 🟥 **製品層・自作の部品には `data-slot` が無いものがある**——**そこで破綻するかを数えていない**
- 🟨 **「部品が描かれない状態」を story にしてよいか自体が未決**（本件の `Sidebar/Mobile` は
  **開く前の 0 件を主張してから開く**形にした＝ **0 件であることを明示的に測っている**）
