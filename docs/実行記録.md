### PoC との差分（移送時に効く。手9 で解決する）

| # | 差分 | 理由 | 🟥 移送時の扱い |
|---|---|---|---|
| 1 | `tsconfig.json` に `paths: { "@/*": ["./src/*"] }` を追加 | **shadcn/ui が既定で要求する**（`components.json` の aliases） | PoC の `apps/redmine/tsconfig.json` に**エイリアスが無い**。PoC 側に足すか、移送時に相対パスへ書き換えるか |
| 2 | `next.config.ts` から `output: 'standalone'` と `outputFileTracingRoot` を落とした | monorepo でのコンテナ配布用。本 repo は単体アプリ | 移送先では PoC 側の設定が正。差分を持ち込まない |
| 3 | ESLint から **fetch 直書き禁止**と **`no-restricted-imports`** を落とした | 本 repo に守る対象（`src/lib/api/` の mutator・生成 hooks・`redmine-api`）が存在しない | **本 repo で lint が緑でも、PoC で緑とは限らない。**移送後に PoC 側で再走が要る |
| 4 | ESLint の **Server Actions 禁止は残した** | 部品層でも第 2 の経路を作らない趣旨は同じ | そのまま |
| 5 | shadcn が置く `src/components/ui/**` を **ignore しない** | orval のような生成物ではなく自分で編集する実体コード。ignore すると「shadcn の素のコードが strictTypeChecked と任意値禁止を通るか」（手1 の観測）ができなくなる | PoC 側でも同じ扱いにするかは手9 |

### 気づき（PoC へ戻す候補）

- 🟦 **`@tailwindcss/postcss` が PoC の catalog に無い。**Tailwind v4 は「PostCSS プラグイン 1 個 + CSS の `@import`」で配線するが、そのプラグインが catalog にも `apps/redmine` の依存にも無い。**Tailwind が配線されていないことの機械的な証拠**であり、`theme.css` が孤立資産になっている理由でもある。→ PoC の OBS 候補（手9 でまとめて起票）。
- 🟥 **Next.js 16 は build 時に `tsconfig.json` を書き換える。**実測で `jsx` を `preserve` → **`react-jsx`** に変更し、`esModuleInterop: true`・`resolveJsonModule: true`・`.next/dev/types/**/*.ts` を追記した。
  PoC の `@repo/typescript-config/nextjs.json` は `"jsx": "preserve"` を宣言しているが、**app 側の tsconfig に `react-jsx` が書き込まれれば共有設定の宣言は実質無効になる**。PoC の `apps/redmine/tsconfig.json` には現在それらの追記が無く、一方で handoff は `pnpm --filter redmine build` が緑だったと記録している——**この 2 つは整合しない可能性がある**。→ PoC 側で要確認（`build` を回した後に `git diff apps/redmine/tsconfig.json` を見る）。
  なお **`.claude/hooks/block-product-edit.mjs` は Claude の編集を止めるが、Next 自身の書き換えは止めない**。成果物が「人以外の手」で変わる経路がここにある。

### 気づき（PoC へ戻す候補・手2 以降への申し送り）

- 🟥 **思想①の課題「AI が margin/padding を発明する」を、shadcn 自身がやっている。**
  `text-[0.8rem]` `rounded-[4px]` `min-w-[96px]` `ring-[3px]` 等 8 件は**トークンを差し替えても変わらない**。
  → **手5 の「箱を触らずテーマだけ変える」は、最初から部分的にしか成立しない。**
  手5 の判定を「変わったか / 変わらなかったか」の二値でなく、**「どこが変わらなかったか」を列挙する形**に変える必要がある。
- 🟦 **`tailwindcss/no-arbitrary-value` は「値の発明」と「構文上の指定」を区別しない。**
  `transition-[width]` はプロパティ名の指定、`grid-cols-[1fr_auto]` はグリッド定義で、どちらもデザイン値ではない（6 件）。
  **思想①の目的に照らすとルールが過剰検知している。**PoC 側の off リスト議論（ADR-0019）に効く材料。
- 🟥 **`exactOptionalPropertyTypes: true` と shadcn は非互換。**PoC の `base.json` が定めている設定なので**移送時に必ず出る**。
  選択肢は (a) 設定を弱める（移送先の型の厳しさが落ちる）(b) 該当部品を 1 行直す（＝部品を触る）(c) `DropdownMenuCheckboxItem` を使わない。**手3 で決める。**
- 🟨 **Sidebar が突出して重い**（32 export・lint 33 件中 17 件・唯一 state を内包）。手3 の作業はここに集中する。
  一方 **Overlay 系は shadcn が十分に供給しており自作不要**——思想が Layout と Overlay を「同格で自作テンプレとして持つ」としたのは、**Layout については正しく、Overlay については過剰**だった。
- 🟦 **preset の実体は `@import "shadcn/tailwind.css"`。**設計システムはコード生成ではなく **CSS の import 1 行**で入る。
  だから `shadcn` パッケージ自体が `dependencies` に入る。**preset の差し替えが軽い**（公式が「別の code で init し直せば再構成される」と言う）理由がこれ。
- 🟨 **shadcn が追加した依存は `^` レンジ**（`class-variance-authority` `clsx` `lucide-react` `radix-ui` `shadcn` `tailwind-merge` `tw-animate-css`）。
  PoC は ADR-0012 で**厳密ピン**が方針。**移送時にピンし直しが要る。**また `shadcn`（CLI）が `dependencies` に入るのは
  本来 `devDependencies` が適切だが、preset の CSS を import しているため**ランタイム依存として正しい**。
