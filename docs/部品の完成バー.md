## 2. 面①「描画された」の定義

```
story を描いたあと、document に「意味のある中身」が 1 つ以上ある
```

🟥 **`#storybook-root` を見てはいけない**（罠 3）。**`document.body` を見る。**
🟥 **`textContent` の有無で判定してはいけない**——`Spacer` / `Separator` は**文字を持たない部品**で、
文字で測ると「対象 0 件で緑」の逆（**正しい部品を落とす**）が起きる。

**判定**: `document.body` の中に、`#storybook-root` の子孫 **または** portal の子孫として、
**要素が 1 つ以上あり、その少なくとも 1 つが 0 でない大きさを持つ**こと。

### 🆕 実装（部品1 B1-06a・2026-08-09）

`.storybook/preview.tsx` の **`export const afterEach`**。**全 story に自動で掛かる**（D10=A）。

```ts
const isHarness = (el) => el.classList.contains('sb-wrapper') || el.id === 'storybook-a11y-vision-filters'
const portalRoots = (canvasElement) =>
  [...document.body.children].filter((el) => !isHarness(el) && !el.contains(canvasElement))
// canvas ＋ portal の子孫に、大きさが 0 でない要素が 1 つ以上あるか
```

🟥 **書くときの落とし穴 3 つ**（全部 B1-06a の実測）:

1. **`canvasElement` は無名の `<div>`**（`#storybook-root` **ではない**）——**id では掴めない。参照で比べる。**
2. **harness は毎回この 5 件**（`.sb-preparing-story` / `.sb-preparing-docs` / `.sb-nopreview` /
   `.sb-errordisplay` ＋ `svg#storybook-a11y-vision-filters`）——**除かないと全 story が緑になる。**
3. **待つ。**同期に測ると CSS が当たる前の大きさ（0）を読み、**正しい部品を落とす**（[DR-0094](DR/DR-0094-the-bar-engine-ran-without-any-css.md) と同じ形）。

🟦 **両方向で確かめた**（K6 / K7）——**空 story だけが落ち**、
**`Dialog/Open`（portal）・`Spacer`・`Separator`（文字なし）は通る。**

## 5. 面④「語彙の効果」

```
語彙 prop を指定したら、実効値（getComputedStyle / getBoundingClientRect）がその語のとおりになる
```

🟥 **「指定した」ではなく「効いた」を測る。**[DR-0090](DR/DR-0090-token-classes-were-silently-dropped-by-tailwind-merge.md) の実測——
`SelectTrigger` の `width` は **3 語とも一度も効いていなかった**（`twMerge('w-fit w-field-md')` が両方残し、CSS 順で `w-fit` が勝つ）。
**prop も型も lint も story も緑で、作用だけが無かった。**

🟨 **語彙を 1 語足したら `src/lib/tw-merge.ts` にも足す**——**語彙の写しが `tokens.css` と 2 箇所にあり、機械で守られていない**（工程外の修正が残した宿題 ①）。

### 🆕 🟥 story に生値（`'6px'`）を書かない（部品1 B1-06b の実測）

**`tokens.css` の宣言を読んで期待値を書いたら、3 件が外れた**——

| 語 | tokens.css の宣言 | 実効値 |
| --- | --- | --- |
| `--spacing-inline-sm` | `calc(--spacing * 1.5)` = **6px** | 🟥 **4px** |
| `--container-content` | `--container-4xl` = **896px** | 🟥 **980px** |
| `--text-heading` | `--text-lg` = **18px** | 🟥 **17px** |

**原因は `src/styles/tmp-admin.css` が `:root:root` の詳細度で上書きしているから**＝
🟦 **[DR-0005](DR/DR-0005-token-ownership-and-two-stage.md)「値は tmp-admin を引き継ぐ」のとおりで、仕様。**

★★★ **だから面④ の主張は「このクラスは**このトークン**を指している」に絞る。**
**生値を書くと ① 二重管理を 1 つ増やし ② 手5 のトークン差し替えのたびに story が壊れる**——
**差し替えられることこそがこの repo の目的**（[DR-0078](DR/DR-0078-repo-becomes-a-ui-factory-for-a-core-design-system.md)）なのに。

```ts
// 値そのものの妥当性は ① 層の話であって面④ の話ではない
await expect(styleOf(canvas, 'box-md').paddingTop)
  .toBe(resolveLength(canvas, '--spacing-inset-md'))
```

🟦 **共通の測り方は `src/stories/measure.ts`**（`el` / `styleOf` / `boxOf` / `resolveLength` / `resolveColor`）。
🟥 **`?.` を使わない**——`querySelector(…)?.getBoundingClientRect().width` は**要素が無いと `undefined` を返し、
`expect(undefined).not.toBe(...)` が通る**＝ **「対象 0 件で緑」の play 版。**`el()` は**無ければ throw する。**

### 🆕 面④ の測り方（部品2 C2-05 で実装した・2026-08-09）

**story の `play` 関数**で測る。**バーの実行エンジン（`pnpm test-storybook`）の中**で走るので、
別スクリプトのように「回し忘れる」経路が無い（部品1 D7 と同じ理由）。

```ts
play: async ({ canvasElement }) => {
  await waitFor(async () => { await expect(width('#sw-sm')).toBe(24) })
  await expect(width('#sw-md')).toBe(32)
  await expect(width('#sw-sm')).not.toBe(width('#sw-md'))  // 語が別の値になっていること
}
```

🟥 **書くときの落とし穴 3 つ**（全部 C2-05 で踏んだ）:

1. **`waitFor` で囲む。**同期に測ると **CSS が当たる前の値**を読む。
2. **`expect` は `await` する。**`storybook/test` の `expect` は Promise を返すので
   付けないと `no-floating-promises` が出る（🟦 実行時は instrumenter が await するので**落ちはする**）。
3. ★★★ 🟥 **`vitest.config.ts` に `@tailwindcss/vite` が要る。**
   無いと **CSS が 1 行も当たらず、正しい部品を落とす**（[DR-0094](DR/DR-0094-the-bar-engine-ran-without-any-css.md)）。
   **1 と 2 を直しても直らないので、まず 3 を疑う。**

🟨 **単調性まで測る**——`SelectTrigger` の 3 語は **sm > lg の逆転**だった（[DR-0090](DR/DR-0090-token-classes-were-silently-dropped-by-tailwind-merge.md)）。
「値が入っている」ではなく「**語の順序どおりに並んでいる**」を見る。
